# Subtask 03 (C): simple project workflow and one replay report

## Goal
Give users a Create ML style path through real projects, folder import, data understanding, one-engine training and a single graphical result.

## Owner files
`src/pdm/app.py`, new `src/pdm/project_ui.py`, `src/pdm/project_quality_ui.py`, `src/pdm/project_training_ui.py`, `src/pdm/project_results_ui.py`, related CSS only where needed, and focused `tests/test_project_ui.py`, `tests/test_project_replay.py`. Consume A/B APIs; do not change import/model internals or `worker.py`.

## Acceptance criteria
- [x] Use A's `project_store()` and `load_snapshot()` mapping contracts plus B's `list_project_runs()`, `load_signal_run()`, `status_for_project()` and `forecast_prefix()`; no private storage inference in UI. Project landing lists all persistent projects by user name, including linked legacy ones when actual artifacts exist. Create persists an empty project, then offers Delete project with confirmation and recoverable archive receipt. Switching project clears playback/run-specific session state. Restart preserves list/selected record from registry, not just session state.
- [x] Import screen leads with **Choose folder**, using installed Streamlit `file_uploader(..., accept_multiple_files="directory")`, with separately controlled Validation and Testing automatic/folder choices. Server-visible path is secondary for multi-GB sources. Show editable desired auto weights (default 70/15/15), explain renormalization when a manual set is supplied, and show actual whole-unit counts; include source kind, generic signal/time schema, yellow/red thresholds, preflight and actionable errors. Do not claim the browser picker reads a local path without upload.
- [x] Data Quality is organized around Train, Validation, Testing: units, rows, time spans, missing/rejected/gap counts, signal range, observed-vs-censored or unknown future target counts where meaningful, and a selected unit signal plot. Explain what was admitted and why training is allowed/blocked in plain language. Keep raw `dataset_version`, split hash and debug JSON out of primary content.
- [x] Training offers exactly one eligible engine selector per run, engine-specific validated parameter controls, and Train. Show `status_for_project(pid)` only, with matching job ID and final validation/test summary. Unavailable research engines may be explained in help text, but are absent from the launch selector. No old future-red multi-select as the main action. Linked legacy snapshots require a newly trained compatible signal run before Results unlocks.
- [x] Results is **one** chart/report with gray actual observations through the Play cursor, yellow/red limit lines or valid stepped threshold trace, forecast points/line beyond cursor in a distinct style, horizon/units/crossing status and a compact metric summary. Display red crossing as first supported discrete forecast point, with honest no-crossing/unavailable text. Play, pause, reset and unit/run selection persist correctly. `selected_run_id` is stored via `ProjectStore.update()` after verifying the run; never show hidden actual future on the chart at an earlier cursor. No old report-view radio or advanced branch in the new product navigation; legacy APIs/CLI remain intact.
- [x] AppTest verifies empty workspace, import/error states, two project switches, active worker, locked steps, deletion, selected run binding, Play cursor, mobile/desktop-safe layout and meaningful control labels. Existing helper tests are retained or adjusted to test their preserved APIs without forcing an old visible report chooser.
