# Application joint-training route audit

Source-only inspection, 2026-10-03. No existing file was changed; no producer output, dataset, frame, NPZ or checkpoint was read; no project model import, construction, forward, training, inference or matrix execution occurred. The live matched GRU producer was left untouched. This report establishes source routes, not runtime or model-quality evidence.

## Normal Training launch and uncertainty mode

The shared numeric registry is GRU, LSTM, Quantile Boosting and Full MaleCNS (`src/pdm/signal_training.py:30`). Normal project Training chooses the learned Bearings profile first and falls back to the residual profile (`src/pdm/project_training_ui.py:168`). The learned profile admits a snapshot when its signal label is exactly **Combined max-axis RMS**; it does not make a scientific acceptance decision (`src/pdm/signal_profiles.py:60`). All four registered engines can receive `learned_joint_trajectories` through this branch. Other signal labels use `joint_residual_paths` (`src/pdm/signal_profiles.py:43`); direct API calls without that flag use legacy mode (`src/pdm/signal_training.py:79`).

Normal **Train model** submits the chosen profile plus visible form overrides as a `project_train` worker job (`src/pdm/project_training_ui.py:238`, `src/pdm/project_training_ui.py:265`). CLI and worker validate/dispatch that job (`src/pdm/cli.py:104`, `src/pdm/worker.py:267`), `train_project_job` passes params to `train_signal_run` (`src/pdm/project_tasks.py:18`), and the learned mode branch invokes `train_learned_run` (`src/pdm/signal_training.py:664`). There is no separate learned-objective mode selector in this form; routing follows the snapshot label/profile.

The matrix differs: `scripts/run_signal_funnel_matrix.py:53` creates all four engine jobs with **funnel_training_profile only**, so its current route is the older residual bank even for Bearings. Its freeze declares a sparse Train-supported grid, capped origins and explored/reused-data evaluation (`scripts/run_signal_funnel_matrix.py:58`). The older route builds grouped OOF residual paths, fits the final predictor and then uses Validation for band calibration (`src/pdm/signal_training.py:523`, `src/pdm/signal_training.py:672`). Those fitted predictor gradients are not the learned joint width/RED-corridor gradients described below.

## Objective and backpropagation

All four learned engines share `SignalDistribution.objective`. The production training closure forwards original mask, recorded-entry compatibility, observed-event flag and contiguous no-entry prefix, sample count, coefficients and optional prefix/geometry settings (`src/pdm/learned_trajectory.py:1038`). It balances terms, forms the weighted sum, calls backward, clips model gradients at5 and steps AdamW (`src/pdm/learned_trajectory.py:1076`, `src/pdm/learned_trajectory.py:1118`).

| Learned engine | Optimized by joint loss | Fixed outside joint backpropagation |
| --- | --- | --- |
| GRU | GRU encoder, event head and path MLP | Train-fitted scaler and causal feature construction |
| LSTM | LSTM encoder, event head and path MLP | Same scaler/feature contract |
| Quantile Boosting | Neural external-feature MLP encoder plus event/path heads | Train-fitted quantile trees and censor-aware event classifier/constant heads |
| Full MaleCNS | Neural external-feature MLP encoder plus event/path heads | Complete connectome operator, projection, pooling and per-window reset dynamics |

Recurrent versus external-feature encoders are explicit at `src/pdm/models/signal_distribution.py:93`. Boosting trees are fitted on Train and supply fixed features; the source explicitly excludes neural gradients through trees (`src/pdm/learned_trajectory.py:938`, `src/pdm/learned_trajectory.py:983`). Full MaleCNS transforms raw causal windows into NumPy features (`src/pdm/learned_trajectory.py:833`); its sparse operator/input/bias/pooling are copied into the adapter, and every history window starts with zero neuron state (`src/pdm/models/signal_full_cns.py:30`, `src/pdm/models/signal_full_cns.py:49`). The original anatomical graph is not learned by the joint objective.

Path loss uses a simultaneous band from maximum standardized path excursion, mean known-coordinate width and worst below/above target miss, scaled by the frozen RED threshold (`src/pdm/trajectory_objectives.py:20`, `src/pdm/trajectory_objectives.py:38`). `issued_prefix` constructs geometry before observation masking; `observed_prefix` masks band geometry. Sampled categorical score surrogates augment gradients while preserving forward loss values (`src/pdm/models/signal_distribution.py:598`). Thus width/miss can affect path parameters and event probabilities; they are not display-only statistics.

First-entry likelihood sums probability over compatible recorded-entry buckets or contiguous observed survival. Gaps/censoring do not become negative padded labels (`src/pdm/trajectory_objectives.py:143`). Frame creation uses the uninterrupted known future grid, with a separate first-ever warning eligibility flag requiring the first segment and no previous RED (`src/pdm/trajectory_data.py:191`, `src/pdm/trajectory_data.py:223`). The learned event objective is first future entry from an origin currently below RED, including eligible re-entry origins; **first-ever warning evaluation has the stricter warning mask**. The event likelihood excludes currently RED origins (`src/pdm/models/signal_distribution.py:624`).

Optional RED corridor width/miss uses unconditional event draws and categorical score gradients; known compatible evidence controls miss, while width is a prior even on unknown targets. Its finite-S regularizer is not the native runtime corridor decoder or a calibration guarantee (`src/pdm/trajectory_objectives.py:291`, `src/pdm/trajectory_objectives.py:348`). Optional finite-bound and known-CDF terms are added separately (`src/pdm/models/signal_distribution.py:675`). This common objective can train the neural parameters of all four learned engines, without training their fixed trees/graph.

## Current defaults and eventual profile propagation

The current Bearings application profile is hidden128/depth2,150 epochs, cap256 origins per unit, S32 training/S256 native, batch32, patience25, seed20261002; energy1, width.2, miss5, event.5 and phase.5 (`src/pdm/signal_profiles.py:66`). Inherited learned defaults use row permutation, dropout.1, observed-prefix geometry, lognormal-cure events, shared covariance, absolute sensor features and no explicit objective prefixes. RED corridor width/miss, finite-bound and event-CDF coefficients are **zero**, and post-factor smoothness is zero (`src/pdm/learned_trajectory.py:161`). Constructor event-head weights are small random normal values; normal production fitting does not apply the study's zero-event-head convention (`src/pdm/models/signal_distribution.py:116`, `src/pdm/learned_trajectory.py:1022`).

Smallest eventual application propagation, **if a profile is later accepted**, is an explicit dataset-scoped profile in `signal_profiles.py` carrying the full accepted learned config, consumed by the existing normal Training merge/worker/learned-params route. Keep unsupported datasets on their existing fallback. Make the matrix consume that same accepted profile resolver rather than forcing `funnel_training_profile`; freeze its resolved params, source identities, split/fingerprint, horizon/feature/weight/sampling laws and evaluation interpretation. Generic learned defaults need not change, and exposing nine individual coefficients in normal UI is unnecessary. Save a clear profile identity with the run contract to distinguish new runs from older saved models.

The study's nine active coefficients, history8,33-feature contract, H30/H519 objective prefixes, S128/S256, clip5 and hidden64/128 contrast are experimental; they are not accepted application defaults. Merely changing coefficients does **not** reproduce that experiment: normal fitting selects the best Validation joint objective and uses patience-based early stopping (`src/pdm/learned_trajectory.py:1139`, `src/pdm/learned_trajectory.py:1177`), whereas the isolated study is fresh zero-head Train-only terminal40. Any eventual accepted application initialization/selection policy must be specified explicitly rather than implied by profile weights. No adoption or source edit is proposed now.

## Saved bundle and native Results laws

Preserve config, Train scaler, external scaler, feature order, selection/objective metadata, checkpoint, trace and external encoder where applicable (`src/pdm/learned_trajectory.py:1577`). Normal load checks snapshot fingerprint/schema, artifact hashes, manifest/training-contract agreement and learned reload verification; Full MaleCNS requires complete real-graph provenance (`src/pdm/signal_training.py:847`). Learned loading also checks objective-family/geometry/sampling contracts against saved config (`src/pdm/learned_trajectory.py:1660`, `src/pdm/learned_trajectory.py:1720`). Normal saving verifies native predictions before/after reload, evaluates full Validation and Test frames and binds the selected run (`src/pdm/learned_trajectory.py:1858`). These normal application checks are distinct from the isolated producer's saved-state/RNG parity.

Native prediction uses saved feature order/scalers/encoder and per-origin deterministic identity seeds; it samples the saved dense joint grid and emits simultaneous bands, median and native event probabilities (`src/pdm/learned_trajectory.py:1244`). Results replay is bound to the saved snapshot's Test units, uses only the observed prefix at/before asof, rejects learned threshold overrides, and is direct-only (`src/pdm/signal_inference.py:167`). A shortened requested span still samples the immutable full model grid, recomputes the band for that declared prefix and coarsens late event mass into survival (`src/pdm/learned_trajectory.py:1936`). Never substitute isolated fixed-objective q for native issued q.

Runtime RED corridor remains unconditional including horizon survival, with potentially censored bounds and an uncalibrated label (`src/pdm/trajectory_evaluation.py:40`). Useful warning evaluation requires event probability>=.5, finite width<=900s, entire recorded bracket contained and actual bracket-left lead>=600s; there is no predicted-left-lead gate (`src/pdm/trajectory_evaluation.py:219`). Results uses saved learned thresholds/horizons and exposes Test summary metrics (`src/pdm/project_results_ui.py:466`).
