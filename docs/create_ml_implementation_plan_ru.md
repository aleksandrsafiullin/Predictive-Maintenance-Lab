# План внедрения: проекты, данные, обучение и прогноз

Дата: 29 сентября 2026 года.

Статус: этапы A–D выполнены. Итоговая проверка — 581 тестов и браузерный сценарий с настоящим обучением. [Отчёт о выполнении и ограничения](create_ml_implementation_report_ru.md).

## Целевой сценарий

**Создать проект → Import data → Data Quality → Training → Results.**

Проект имеет своё имя, данные, настройки и сохранённые модели. Пользователь выбирает папку, проверяет три выборки, выбирает одну модель и запускает обучение. На единственном экране Results кнопка Play последовательно раскрывает измерения и показывает прогноз модели на выбранный момент.

## Этапы

| Этап | Что меняется | Приёмка |
|---|---|---|
| A. Проекты и данные | Постоянный список проектов; создание и восстановимое удаление; импорт папки; отдельные Training, Validation, Testing | Два проекта одного типа независимы. Перезапуск сохраняет данные. Удаление не затрагивает другой проект и исходные файлы существующих датасетов |
| B. Обучение и прогноз | Сохранённые модели прогноза сигнала; параметры выбранной модели; фоновые задания и остановка | Параметры действительно используются. Модель обучается на Training, выбирается по Validation и проверяется на Testing. Прогноз воспроизводится после загрузки |
| C. Интерфейс | Четыре рабочих экрана без отладочного шума и переключателя Report view | Можно пройти путь от создания проекта до Play. Data Quality объясняет состав выборок и проблемы данных. Элементы управления читаемы на широком и узком экране |
| D. Независимая проверка | Ревью кода, автоматические тесты и браузерная проверка на реальных измерениях | Все замечания, влияющие на требования, исправлены. Результаты проверок и непроверенные ограничения записаны отдельно |

Реализацию выполняют субагенты GPT-6 SOL. Оркестратор проверяет архитектуру, интеграцию и выполнение критериев. Общение между агентами ведётся на английском, отчёты пользователю — на русском.

## Решения по данным

- **Project не равен типу датасета.** Bearings и Filters становятся существующими проектами; можно создавать дополнительные проекты того же или другого типа.
- Для новых типов оборудования поддерживается CSV с идентификатором оборудования, временем в секундах и выбранным числовым показателем. Название, единица показателя и пороги задаются явно.
- Основной способ импорта — выбор папки. Для больших источников доступен локальный путь на компьютере, где работает приложение.
- Validation и Testing независимо выбираются из отдельных папок или автоматически выделяются из Training pool.
- Автоматическое разделение распределяет целые истории оборудования. По умолчанию используются веса 70/15/15. При вручную заданной выборке её размер не меняется; оставшиеся веса нормируются для общего набора. Интерфейс показывает фактические количества.
- Пропуски и отклонённые измерения сохраняются в отчёте качества и разрывают непрерывную историю модели.
- Существующие исходники не копируются при регистрации старых проектов. Для нового обучения сохраняется собственная небольшая версия подготовленных данных.

## Training

Первый набор моделей для нового прогноза сигнала: GRU, LSTM и градиентный бустинг. Пользователь выбирает одну модель, задаёт её параметры и запускает обучение. Тяжёлая работа выполняется в фоне, со статусом и остановкой, привязанными к проекту.

Исследовательские реализации Fly, Random и Full CNS сохраняются. Их существующий прогноз вероятности красной зоны или RUL нельзя выдавать за прогноз траектории измеряемого сигнала. Для включения этих движков в новый экран требуется отдельная проверенная реализация прогноза сигнала.

## Единственный Results

- Серая линия — фактические измерения до текущего положения Play.
- Жёлтая и красная линии — заданные пороги в единицах показателя.
- Отдельная линия — прогноз сохранённой модели для будущих моментов.
- Время входа в красную зону — первая поддерживаемая прогнозная точка, пересекающая порог. Если пересечение в горизонте не прогнозируется, интерфейс сообщает это прямо.
- Play, Pause и Reset управляют одной временной шкалой. Переключение проекта, модели или оборудования сбрасывает несовместимое состояние воспроизведения.

Модель на момент `t` получает только измерения с временем не позднее `t`. Будущие фактические значения не подставляются в прогноз. Интервал неопределённости не изображается как гарантированная вероятность без соответствующей проверки.

## Контроль качества

Исходное состояние перед работой: 534 теста прошли, Ruff замечаний не нашёл. Предшествующие незавершённые изменения сохранены; исторический план интерфейса не заменяется.

Финальная проверка включает создание и удаление проектов, четыре сочетания автоматических и ручных выборок, повторную загрузку модели, фоновые задания, причинность прогноза, полный набор тестов и работу интерфейса в браузере. Успешный короткий запуск обучения подтверждает работоспособность сценария, но сам по себе не подтверждает качество промышленного прогнозирования.
