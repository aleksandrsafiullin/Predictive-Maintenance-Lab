## Исходные замечания до исправления

### 1. P2 — официальная Testing-папка HSE ошибочно считается пустой

Воспроизведение: проект HSE, Training-папка с `Train_Data_CSV.csv`, автоматическая Validation, **Separate folder** для Testing с `Test_Data_CSV.csv`. `import_project()` возвращает `ValueError: Separate test folder has no admitted units` при корректных измерениях.

Причина: адаптер присваивает официальным Test-историям `source_group="author_test"` независимо от папки. В `allocate_project_split()` проверка отдельной папки учитывает только группу `test` и выполняется до обработки `author_test` ([код](../src/pdm/data/project_prepare.py), строки 50–62 и 287). Следует учитывать официальные Test-истории именно из выбранного Testing-источника при проверке его наполненности, сохраняя запрет переноса этих историй в обучение. Нужен регрессионный сценарий HSE с отдельным официальным Test-файлом; существующая проверка четырёх сочетаний авто/ручного разделения использует Sensor CSV.

Проверено на синтетических HSE CSV через существующий `_write_filter`: 4 Train-истории и 1 официальная Test-история. После переноса того же Test-файла в Training-папку и выбора **Split from training** импорт успешен: **3 / 1 / 1**. Это временный обход проблемы; официальный Test остаётся Testing.

### 2. P2 — редактор порогов ломает график на узком экране

На **390 × 844** график Data Quality сжимается примерно до 128 px, а панель порогов частично обрезается справа. Легенда и подписи графика не помещаются. Причина — `wrap=False` у пары график/редактор ([код](../src/pdm/project_quality_ui.py), строка 410) вместе с фиксированной шириной панели 220 px ([CSS](../src/pdm/visualization/explorer.css), строки 46–58). Для узкого экрана нужен перенос панели под график и снятие фиксированной ширины; настольное расположение можно сохранить.

Подтверждено визуально: [узкий экран](../output/playwright/review-quality-mobile.png), [настольный экран](../output/playwright/review-quality-desktop.png). Проверка ширины всей страницы сама по себе не обнаруживает обрезку внутри контейнеров.

### 3. P2 — Split settings почти не читается в светлой теме

На Import data кнопка **Split settings** сохраняет тёмный фон нативного Streamlit, а подпись получает тёмный цвет светлой темы. Измеренные браузером цвета: фон `rgb(22, 22, 24)`, текст `rgb(29, 29, 31)`. В [общих стилях кнопок](../src/pdm/visualization/explorer.css), строки 105–107, охвачены `stButton` и `stFormSubmitButton`, но новый `stPopoverButton` не охвачен. Нужно согласовать фон, текст и состояния этой кнопки с токенами темы.

Подтверждение: [Import data, светлая тема](../output/playwright/review-import-desktop.png). Кнопка работает, но её название практически не видно.

### 4. P2 — полный набор тестов не проходит после изменения индикатора этапов

`tests/test_worker_and_app.py::test_explorer_css_has_no_glow_or_gradient` падает на строке 692: ожидается один `linear-gradient` для slider, фактически их два. Новый градиент в [CSS](../src/pdm/visualization/explorer.css), строка 99, рисует двухцветный участок индикатора этапов. Это конфликт нового дизайна с прежним тестовым контрактом, а не доказательство ошибки обучения. Следует либо реализовать индикатор без градиента, либо явно разрешить именно этот селектор в проверке, сохранив контроль остальных декоративных градиентов.

## Что подтверждено

- Полные истории единиц оборудования распределяются между Train/Validation/Test без пересечения; автоматические веса нормализуются по оставшимся автоматическим группам.
- Предобработка и параметры временного шага вычисляются по Training; выбор модели использует Validation. Test-окна для оценки строятся после выбора модели.
- Перенос единиц создаёт новый снимок, сохраняет старый и сбрасывает выбранную модель; прежние модели не выдаются за модели нового разделения. Официальный HSE Test защищён от переноса в обучение.
- Сохранение порогов пишет отдельный `zone_limits.json` без изменения отпечатка снимка и модели. Results использует сохранённые пороги; черновик Data Quality остаётся предпросмотром.
- Карточки показывают состав сохранённого снимка. Переход **Testing Data → View** открывает соответствующую вкладку Data Quality.
